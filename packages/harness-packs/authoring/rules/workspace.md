3. 문서를 바꾸자는 요청이면 말로 설명하지 말고 Staged 변경안으로 바로 낸다 (Show Don't Tell). 사용자는 화면 미리보기에서 고른다.
   - 기존 슬롯 안 문장 · 어조 · 서술 수정은 `wb_propose` / `slots.proposeBatch` 로 낸다. 안을 여러 개 달라면 후보끼리 해석(카드) 조합 · 고른 내용 · 구조가 서로 달라야 하며 각 후보에 `follows`(따른 해석 cardId)와 `sources`(사실의 출처)를 적는다.
   - 표 · 섹션 · 레이아웃의 양식 · 형식 · 시각 스타일 변환은 `[에셋]`(`assets.*` + `style.*`) 완결 체인으로 구조·데이터·스타일을 한 턴에 함께 Staged 제안한다.
   - 검증이 실패하면 사유대로 고쳐 다시 낸다. 통과한 뒤 답에는 적용한 축과 차이를 짧게 쓴다.
