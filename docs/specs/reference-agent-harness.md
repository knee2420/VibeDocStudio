# 레퍼런스 에이전트 하네스 — 조율 · 합의 · 부분 채택

## 1. 목적

레퍼런스는 **의도**다. 남이 비슷한 문제를 풀며 내린 결정의 궤적을 층위(D1–D6 · U1–U7)로 분해해 내 문서에 옮긴다.
그런데 같은 레퍼런스를 사람마다 다르게 읽고(해석이 갈린다), "레퍼런스로 삼아 달라"는 통째 복제가 아니라 **일부분**일 수 있다.
그래서 하네스의 기준 데이터는 리소스의 "읽은 줄"이 아니라 **합의 기록**이다.

    해석 제안(AI) → 조율(사용자) → 합의 기록(저장) → 적용(AI) → 검토(코드)

## 2. 작업 달성 목표 (절차)

모든 레퍼런스 요청은 아래 절차를 따른다. 각 단계는 도구 기록으로 확인할 수 있어야 한다 (평가가 이것을 잰다).

| 단계 | 달성 목표 | 확인 근거 |
|---|---|---|
| G1 범위 판정 | 요청이 어느 레퍼런스 · 어느 범위(전체 · 쪽 · 핀) · 어느 층위를 말하는지 정한다. 레퍼런스와 무관한 요청이면 열지 않고 이유를 밝힌다 | 생각 첫 줄 · `확인하지 않은 출처` 줄 |
| G2 합의 확인 | `rf_consensus` 로 확정된 해석과 채택 강도를 먼저 본다. 확정 카드가 요청을 덮으면 다시 해석하지 않는다 | `rf_consensus` 호출 |
| G3 근거 읽기 | 범위를 실제로 읽는다. 핀이 있으면 핀부터. 긴 레퍼런스는 이어 읽기로 범위를 덮는다 | 레퍼런스 읽은 범위 원장 (`rf_coverage`) |
| G4 해석 제안 | 합의가 없는 층위는 `rf_interpret` 로 해석 카드를 낸다 (근거 앵커는 읽은 곳만). 해석이 갈리면 대안 해석을 함께 낸다 | 카드 검증 결과 |
| G5 적용 | 문서를 바꾸는 요청이면 `wb_propose` 후보마다 따른 카드(`follows`)를 적는다. 따르지 않음 층위는 닮아 가지 않는다. 모호한 요청은 해석별로 다른 후보를 낸다 | 제안 검증 (따름 · 비채택 · 누출) |
| G6 보고 | 무엇을 따랐고 무엇을 안 따랐는지, 덜 읽은 곳, 사용자가 확정할 카드를 짧게 밝힌다 | 답변 |

사용자가 요청 문장으로 채택을 직접 말하면("톤만", "표는 빼고") 그 턴의 지시로 보고 카드를 그 강도로 내고 적용한다.
요청이 "이것처럼"처럼 모호하면 해석을 정해 놓고 밀지 않는다 — 해석 후보별 안을 보여 주고 고르게 한다 (Show Don't Tell).

## 3. 이용자 요청 경우의 수

| # | 유형 | 예 | 기대 절차 |
|---|---|---|---|
| Q1 | 통째 모호 | "이 레퍼런스처럼 써줘" | G2 → G3 → G4(갈리는 층위는 대안) → 해석별로 다른 후보 2안 → 확정할 카드 안내 |
| Q2 | 층위 지정 | "어조만 따라해" · "구성 흐름만" | 지정 층위만 따름, 나머지 따르지 않음으로 카드 → 후보는 그 층위만 닮음 |
| Q3 | 영역(핀) 지정 | "이 핀 부분처럼" | 핀부터 읽음 → 범위=핀 카드 → 범위 밖 근거 안 씀 |
| Q4 | 층위 × 영역 | "2쪽 표의 조판만" | 쪽/덩어리 찾기(`rf_find`) → 범위=그 표, 층위=D5 |
| Q5 | 제외 지정 | "표는 빼고" · "이모지는 따라하지 마" | 해당 층위 따르지 않음 → 그쪽으로 닮아 가지 않음 |
| Q6 | 강도 지정 | "참고만" · "최대한 비슷하게" | 참고 = 검토 완화 · 최대한 = 켜진 층위 모두 따름 (내용은 여전히 옮기지 않음) |
| Q7 | 분석 · 해석만 | "이 레퍼런스 뭐가 좋은 거야?" | G3 → G4 카드만 (문서 안 바꿈), 측정값 근거 |
| Q8 | 비교 | "A와 B 차이" · "내 문서는 레퍼런스와 뭐가 달라?" | `rf_contrast` 층위별 → 해석 카드는 필요할 때만 |
| Q9 | 결합 | "A의 구성 + B의 어조" | 레퍼런스별 카드 → 후보가 두 카드를 함께 따름 |
| Q10 | 합의 적용 | "아까 정한 대로 적용해" | `rf_consensus` 확정 카드만 따름 · 다시 해석 안 함 |
| Q11 | 해석 반박 · 수정 | "결론 먼저가 아니라 요약 박스 때문이야" | 해석 수정 카드 제안 (대안을 사용자 해석으로) → 적용은 수정 해석으로 |
| Q12 | 사실 혼동 | "레퍼런스에 나온 수치로 채워줘" | 거절하고 리소스로 돌림 (레퍼런스는 사실 근거가 아님) |
| Q13 | 무관 요청 | "이 문서 몇 쪽이야?" | 레퍼런스 열지 않음 + 이유 |
| Q14 | 긴 레퍼런스 전역 | "이 14쪽 문서 구성 전체를 요약" | `rf_outline` 이어 보기로 전 범위 덮음 → 덮은 범위 밝힘 |
| Q15 | 모호한 위치 | "그 표 있잖아, 그것처럼" | `rf_find kind=table` 로 후보 위치 제시 · 고르게 하거나 가장 그럴듯한 것을 밝히고 진행 |
| Q16 | 핀이 있는데 안 짚음 | 핀 있는 레퍼런스에 "이처럼 다듬어줘" | 핀을 사용자의 초점으로 보고 먼저 읽음 |

## 4. 도구 (실행: `vibefs/ref_tools.py` · 명세: 하네스 팩 `reference:tools.json`, MCP 이름 `rf_*`)

| 도구 | 하는 일 |
|---|---|
| `rf_map` | 켜진 레퍼런스별 지도: 형태 · 쪽 · 섹션 · 쪽별 덩어리 종류 · 핀(층위 태그 · 메모) · 저장된 층위 측정 요약 · 합의 상태 |
| `rf_outline` | 섹션 → 덩어리 id. `offset` 으로 이어 본다 (잘리지 않음) |
| `rf_read` | `ref:<id>[#p<n>|#sec:<n>|#blk:<id>|#pin:<id>]` 읽기 · 이어 읽기 · **읽은 덩어리 기록** |
| `rf_find` | 낱말 · 덩어리 종류(table · heading · list · paragraph) · 쪽으로 위치 찾기 |
| `rf_coverage` | 덩어리 읽음 N/M · 핀 읽음 · 층위별 근거 유무 |
| `rf_measure` | 층위 지표. 레퍼런스 전체는 저장된 측정값, 일부는 그 자리에서 |
| `rf_contrast` | 두 앵커(레퍼런스 · 내 문서 칸 · 이력)를 층위별 비교 |
| `rf_interpret` | 해석 카드 제안 (층위 × 범위 × 채택 강도 × 해석 × 근거 × 대안) — 검증 후 세션에 저장 |
| `rf_consensus` | 확정 카드 + 이 대화에서 낸 미확정 카드 |

`wb_*` 는 에디터 문서 · 이력 전용이다. `ref:` 앵커를 넘기면 `rf_*` 로 안내한다.

## 5. 합의 기록

프로젝트 바인딩 항목(`references/bindings/<projectId>.json` 의 entries[])에 `consensus: [card…]`.

    card = {cardId, layer, scope("ref:<id>[#…]"), adoption(follow|consult|exclude), reading, evidence[앵커],
            alternatives[{reading, evidence}], status(confirmed), by, at}

- AI 가 낸 카드는 세션 저장소(`state/assistant/workspace/interpretations.jsonl`)의 **제안**이다. 사용자가 확정하면 바인딩에 저장된다.
- 기존 층위 켜고 끄기(`layers: {D2: false}`)는 그대로 두고 "따르지 않음"으로 읽는다.

## 6. 검토 (코드)

검증기는 `harness_kit/gates/reference.py`, 순서는 `authoring:proposal.json` 의 candidateGates, 피드백 글은 `reference:messages.json` gates,
임계값은 `reference:layers.json` adoptionCheck 에 있다.

| 검토 | 위치 | 판정 |
|---|---|---|
| 해석 근거 | `rf_interpret` | 근거 앵커가 존재 · 읽은 덩어리 · 범위 안 · 층위 id 가 레지스트리에 있음 · 대안이 첫 해석과 다름 |
| 따름 표시 | `wb_propose` | 레퍼런스가 켜져 있으면 후보마다 `follows`(cardId) — 없거나 모르는 카드면 오류 |
| 따름 준수 | `wb_propose` | 따름 카드 층위에서 레퍼런스와의 거리가 늘지 않음 (지표 없는 층위는 제외) |
| 비채택 침범 | `wb_propose` | 따르지 않음 층위에서 레퍼런스 쪽으로 크게 닮아 감 → 오류 (임계값은 레지스트리) |
| 내용 누출 | `wb_propose` | 레퍼런스 문장 · 수치 · 고유명사 (기존 유지) |
| 깊이 | 출처 집계 | "핀 1/1 · 덩어리 81/209" — 핀을 안 읽었으면 재확인 |

## 7. 평가

`evals/wb_suites/reference.py` 의 `REF` 영역 (모음 · 실행 순서는 `evals/wb_scenarios.py`). Q1–Q16 을 시나리오로 옮기고 일부는 보류 세트(holdout)로 둔다.
긴 실물 레퍼런스(14쪽 PDF)를 픽스처에 포함한다. 여러 턴(해석 → 사용자 확정 → 적용)은 평가기가 사용자 대신 카드를 확정한다.
