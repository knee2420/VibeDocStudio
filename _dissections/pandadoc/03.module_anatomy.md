## 1. 핵심 아키텍처 발견 (우리가 세운 가설과의 100% 일치 증명)

`REA`로 라이브 DOM(4,321개 노드)과 접근성 트리(2,172개 노드), 스크립트 청크(27개)를 해체한 결과, 판다독 에디터(내부 코드네임 **`PandaDoc Kolas Editor`**)의 핵심 구조가 완전히 드러났습니다.

### 🔥 발견 1: 판다독도 문서 전체가 통짜 에디터가 아니라 **"모든 블록과 표의 셀 하나하나가 독립된 미니 에디터(`textbox` 슬롯)"**로 쪼개져 있다!
* 해체된 트리를 보면, 판다독은 페이지 전체를 하나의 `contentEditable`로 묶지 않았습니다.
* 제목(`Venture Proposal Template`), 작성자 정보(`Prepared by`), 본문 단락(`What We Do` 본문), 그리고 **표(`table`) 안의 모든 개별 헤더(`columnheader`)와 셀(`cell`) 내부마다 각각 독립된 `[textbox]`(미니 ProseMirror 인스턴스 = 즉 우리의 `SlotNode`)가 하나씩 따로 마운트**되어 있습니다.
* **의미**: 우리가 설계한 **「바깥 레이아웃/그리드(Puck) + 슬롯 내부 독립 경량 Tiptap(Maily.to)」** 아키텍처가 판다독 `Kolas Editor`의 실제 내부 구현 방식과 **100% 동일한 정석 구조**임이 증명되었습니다!

## 2. 판다독 `Kolas Editor`의 4대 내부 메커니즘

### ① 마이크로프론트엔드 & Iframe 격리 (`Tessera` + `/e/`)
* 바깥 워크스페이스 쉘(`https://app.pandadoc.com/a/`)과 실제 에디터(`https://app.pandadoc.com/e/`, `PandaDoc Kolas Editor`)가 분리되어 있으며, Webpack Module Federation 기반의 `tessera-transport-runtime`으로 상태를 주고받습니다.
* 클라이언트 캐시 및 오프라인 상태는 `IndexedDB`(`PD_EDITOR`)와 `localStorage`(`editor_initial_data_*`)에 직렬화하여 보관합니다.

### ② 페이지(Page) 컨테이너의 4단 샌드위치 구조
각 페이지는 아래 4개 영역이 세로로 조립된 컨테이너입니다:
1. **`Document's header toggle area`** (`Double click to edit header` — 상단 머리글 슬롯)
2. **`Page content area`** (다단 그리드, 표, 텍스트 슬롯, 입력 필드 블록이 배치되는 메인 캔버스)
3. **`Document's footer toggle area`** (`Double click to edit footer` — 하단 바닥글 슬롯)
4. **`Estimated automatic page break on PDF`** (`PDF page break` — 페이지 넘김 경계선)

### ③ 인라인 변수 칩(`[Sender.Company]`) 처리 방식
* 문단 슬롯 내부에서 `[Sender.Company]`, `[Client.FirstName]` 같은 변수 슬롯은 앞뒤에 **Zero-Width Space(`\u200b`)**를 두어 커서 이동과 드래그 선택이 깨지지 않는 독립 Atom 노드로 격리되어 있습니다 (`Maily.to`의 Tiptap `Variable` 노드와 동일한 방식).

### ④ Fillable Field (할당형 슬롯) 구조
* `[group]` 컨테이너 안에 `LabelText > textbox` (예: `'Short Description of Business'`, `'Area(s) of investment'`)와 담당자 배지(`heading[level=4] '서민규 서'`)가 한 세트로 묶여 있습니다.
* 우리 `VibeDocStudio`에서는 이 담당자 배지 자리에 **`[📎 연결된 백데이터 N건]` 배지 + 컴포넌트 부착형 AI Composer**가 들어가면 완벽하게 대칭됩니다.

## 3. 좌측 `Document preview`(멀티페이지 썸네일)의 구현 비밀
* 해체 결과 동일한 문서 노드 트리가 메인 캔버스와 프리뷰 영역에 대칭으로 존재합니다.
* 즉, 무겁게 이미지를 캡처해 띄우는 것이 아니라 **동일한 페이지/슬롯 JSON 트리를 CSS `scale()`로 축소한 읽기 전용 미러 컴포넌트**로 좌측 썸네일을 실시간 렌더링하고 있습니다. (`Puck`의 JSON 트리를 좌측 프리뷰에 그대로 꽂아 `transform: scale(0.18)`만 주면 100% 동일하게 구현 가능!)
