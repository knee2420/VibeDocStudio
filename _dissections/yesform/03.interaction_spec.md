## 3. 선택 영역 반응

- **텍스트 드래그 선택** → 선택 아래에 플로팅 바가 뜸: `AI 제안`(title "더 상세하게 확장") · `요약` · `번역`(영어로) · `문법 수정` · `톤 수정`. 클릭 시 서버 AI를 호출하므로 실행하지 않음.
- **셀 2개 이상 드래그** → CellSelection(셀 하이라이트). 툴바는 표 문맥 그대로.
- **표 안 우클릭** → 커스텀 컨텍스트 메뉴(브라우저 기본 메뉴 차단):
  - `셀 삽입 ▸` (왼쪽에 / 오른쪽에 / 위로 / 아래로)
  - `셀 병합` (셀 1개면 비활성. 2개 선택 시 `colspan:2, colwidth:[a,b]`로 병합)
  - `열 너비 균등하게` (colwidth를 0으로 초기화해 균등 분배)
  - `가로 헤더 추가` / `세로 헤더 추가` (해당 행·열의 셀을 tableHeader로 변환)
  - `열 삭제` · `행 삭제` · `삭제`(표 전체)

## 5. 표 직접 조작

- **열 경계 호버** → 커서 `col-resize`. 드래그 시 인접한 두 열만 서로 너비를 주고받고(193→235 / 64→23px) 표 전체 폭은 유지됨. 결과는 `colwidth`에 저장되는 문서 변경.
- **긴 텍스트 입력** → 행 높이 자동 증가(118→138px). 열 너비는 고정.
- **숫자 셀 수정** → 자동 계산 없음(수량을 바꿔도 공급가액은 그대로).
- **표 위 호버** → 핸들이나 오버레이가 생기지 않음(DOM 변이 0).

## 6. 페이지·문서 수준

- A4(793.69 × 1122.52px, 여백 25.4mm=96px)짜리 흰 페이지 하나. **편집 화면에서 쪽 나눔이 없고**, 내용이 길어지면 같은 페이지 상자가 세로로 늘어남(행 25개 추가 시 2243px).
- 문서 제목은 상단 헤더 input(200px)이며 `doc.attrs.title`에 저장됨.
- 헤더 버튼: `실행 취소` · `다시 실행`(히스토리 없으면 disabled) · `인쇄`(`window.print`) · `다운로드 ▾`(PDF로 다운로드 / PNG로 다운로드 / 이 문서로 전자계약하기 / Docx로 내보내기 / Hwp로 내보내기)
- 템플릿 데이터에는 레이아웃용 인라인 CSS가 `blockStyle` 속성으로 들어 있음(예: `margin-top: 40px`, `margin-bottom: 16px`). 품의서 하단의 "위와 같이 … 제출합니다 / 날짜 / 기안자" 3줄 간격이 이 방식으로 만들어짐.
- 견적서의 `일금 원정 ( ⁭0)`에는 U+206D(보이지 않는 제어문자)가 들어 있음. 금액 자리 표시용으로 보이며 용도는 미확인.

## 7. REA로 확인한 것과 그 한계

- `inspect_web_page`는 이미 로드된 스크립트를 0개로 보고했습니다(REA가 붙기 전에 파싱된 스크립트는 수집하지 않음). 그래서 스크립트 원문 38개는 CDP `Debugger.scriptParsed`로 따로 받았습니다(스크래치 보관, 저장소에는 넣지 않음).
- `inspect_web_event_listeners`(굵게 버튼): 버튼에 `click` 리스너가 직접 하나 붙어 있고 위치는 `18a1ec72573de43a.js:2:349474`(React DOM 런타임)입니다. 실제 동작 로직은 React props 안에 있어서 REA가 말하는 "위임·프레임워크 리스너는 unknown" 범위에 해당합니다.
- `observe_web_execution`(75초): 예스폼 청크 15개에서 함수 약 2,800개가 실행됐습니다. 가장 많이 돈 함수는 ProseMirror 모델(`nodesBetween`, `child`, `nodeSize`), 테이블 데코레이션(`decorations`, `appendTransaction`), 변이 처리(`processMutation`)입니다. 다만 REA 스스로 밝히듯 어떤 클릭이 어떤 함수를 불렀는지는 이 결과만으로 알 수 없어서, 인과관계는 CDP 녹화 쪽으로 채웠습니다.
- 소스맵 URL이 선언돼 있지만 404여서 원래 함수명은 복원하지 못했습니다.
