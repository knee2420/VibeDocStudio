### 1. 결정 카드(Decision) 분석 개요

현재 리소스에 보관된 결정 카드는 크게 **두 가지 계열(기록 출처별 이원화)**로 작성·운영되고 있습니다.

1. **회의 속기 기반 상세 카드 (`_에이전트 작업 공간/.../A5.outputs/D...`)**
   - **성격**: 회의 속기록(타임스탬프)에서 의사결정 발언과 합의 정황을 있는 그대로 추출한 증빙·아카이브형 문서
   - **주 작성 주체**: Claude (회의록 원심분리기/기록 파이프라인)
2. **프로젝트 관리·실행형 결정 카드 (`discussions/.../decisions/Decision...`)**
   - **성격**: 회의 결정 사항을 프로젝트 실행 단위(`1.project`)로 정제하여 Do/Don't 경계와 완료 기준(DoD)을 명시한 기획·실행형 문서
   - **주 작성 주체**: Gemini (R&D 프로젝트 관리)

---

### 2. 공통 형식과 차이점 분석

#### (1) 공통 형식 (Commonalities)
- **속성(Frontmatter) 준수**: YAML 헤더에 유형, 구역, 분류, 주제, 요약, 작성일, 상위, 링크, 담당, 작성자 등 13종 메타데이터 관리.
- **What & Why 분리**: '무엇을 확정했는가(What)'와 '어떤 배경/근거로 그렇게 결정했는가(Why)'를 명확한 계층으로 분리.
- **경계 설정(Boundary)**: 결정이 포괄하는 범위와 명시적으로 배제하는 범위(한다/안 한다, Do/Don't)를 기술.
- **완료 판단 기준 명시**: 단순 선언에 그치지 않고 '끝났다고 보는 기준' 또는 'DoD(Definition of Done)'를 포함.
- **위키링크 연결**: 결정과 연결된 상위 목표(Outcome), 후속 미결 안건(1.1, 1.2 등), 실험 프로토타입(EXP)을 양방향 링크(`[[...]]`)로 결속.

#### (2) 계열별 차이점 (Differences)

| 항목 | 회의 속기 기반 카드 (`A5.outputs`) | 프로젝트 실행형 카드 (`discussions`) |
| :--- | :--- | :--- |
| **Frontmatter 유형/구역** | `유형: 메모`, `구역: 4.archive` | `유형: 할일`, `구역: 1.project` |
| **속기 원문 인용** | **필수 포함**: 발화자·타임스탬프·발언 원문 수록 | **생략**: 정제된 핵심 요약만 수록 |
| **확신도(합의 수준)** | 반대 여부, 주저한 발언, 합의 시점 명시 | 별도 확신도 필드 없이 Callout(`[!check]`)으로 요약 |
| **미결 과제 (`❓ 아직 안 정한 것`)** | 회의 중 남겨진 미지의 영역과 추가 질문을 상세 기록 | 생략되거나 관련 안건 링크(`링크: [[...]]`)로 압축 |
| **실행 가이드라인 진화** | 텍스트 중심의 `어디까지 (한다 / 안 한다)` 서술 | 26.10.02 이후 `3. 실행 가이드라인 (Do / Don't / DoD)` 체계로 구조화 |

### 3. 발전 및 개선 필요점

1. **이원화로 인한 중복 비용**: 회의 아카이브(`D1_...`)와 프로젝트 실행 문서(`Decision 01 — ...`)가 분리되어 있어 동일 결정이 두 벌로 유지되는 비효율이 존재합니다.
2. **실행 책임 누락 문제**: 회의 속기형 카드에서는 `누가`, `언제까지`가 "속기에 없음"으로 처리되어 실제 실행 추적으로 이어지지 못하는 경우가 많았습니다.
3. **가독성과 증빙의 균형**: 실행형 카드는 가독성(Do/Don't/DoD)이 우수하지만 회의 당시의 의사결정 맥락(누가 어떤 반론을 제기했는지 등)이 누락되는 단점이 있습니다.
